## 1. 已确认的目标与本阶段交付物

**用户输入一组感兴趣的中英文论文或文本，系统自动发现论文之间的关联，归纳当前输入文献中的共识与差异，并提供可追溯的证据，为进一步提出新的研究问题提供线索。**

最终产品只要求用户提供文献。研究兴趣或问题是可选输入，人工纳入标准、预先分组、逐篇标注和训练数据都不是产品的使用前提。用户可查看依据、修正结果并追问。人工评价安排在开发验证中，用来检验自动分析是否可靠。

本阶段优先完成 3—5 篇关联论文的完整原型：输入 → 论点提取 → 关联发现 → 共识与差异归纳 → 带证据的报告。现成多语言模型优先，验证效果后再决定是否微调。试点样本用于降低开发复杂度，后续扩展至中文、英文及中英混合集合。

最终报告应回答：

1. 这些论文围绕哪些议题形成关联？关联依据是什么？
2. 哪些具体命题得到一致支持？它们的适用条件是什么？
3. 差异体现于结论、概念定义、机制解释、方法还是研究情境？
4. 哪些研究互补，哪些暂不可比较？有哪些反向证据？
5. 这些比较提示了什么值得继续研究的问题？还需要哪些文献或数据来查证？

共识的范围限定为本次输入。系统产生的问题线索与作者明确陈述的局限分开保存；是否具有领域新颖性需要进一步检索和研究判断。

## 2. 目标流程与设计原则

```text
PDF / 文本输入（兴趣描述可选）
  → 解析、去重、质量标记、来源定位
  → 研究背景与论点提取
  → 相关议题与可比较论点检索
  → 关系判断：一致 / 差异 / 互补 / 暂不可比较
  → 多论文证据综合
  → 共识、差异、关系解释与待探索问题报告
  → 用户查看证据、修正和追问（可选）
```

- 解析与来源档案继续作为基础。对已发现的错误定点修复，避免把全部解析重做变成每次实验的前置工作。
- 文献级 Schema 提供背景；比较单元扩展为“具体论点 + 条件 + 证据”，保存作者自身观点与转述观点的区别。
- TF-IDF 保留为检索基线；多语言嵌入模型负责找候选，LLM 拟承担提取、关系解释与综合。
- DeepSeek 是拟接入的 LLM 选项。现有代码使用 OpenAI Responses API，提供方适配需单独实现和测试，不能直接假定地址替换即可使用。
- 关系判断与综合作为核心模块推进；LLM 全文分析不再列为与主目标无关的可选支线。
- 既比较两篇论文，也围绕共同议题收集多篇证据；A 与 B 相近、B 与 C 相近不能直接证明 A、B、C 共识一致。
- 未命中关系的论文、解析失败或未处理内容应显示在报告中；一次检索的前 12 对不能代表全文集合的全部认识。
- 矩阵、关系图与交互界面在报告验证后推进，微调由可观测的效果瓶颈驱动。

## 4. 分阶段实施计划

### 4.1 任务依赖与完成标准

```text
P0 样本与报告规格
  → P1 证据单元 → P2 论点提取 ─┐
                → P3 检索准备 ─┴→ P3 论点候选 → P4 关系判断
                                                → P5 多论文报告
                                                → P6 人工评价与迭代
                                                → P7 使用入口
```

P2 的服务配置与 P3 的模型准备可以并行。P6 的标注规则可以提前起草，但报告评价依赖 P5 的实际输出。首次完整报告无需等待大规模标注、微调或完整图形界面。

每个阶段按“产物可检查、错误可追溯、符合下述验收条件”推进；不以仅有脚本或模型调用成功代表研究功能完成。以下路径均为**拟新增产物**，当前并不存在；实际命名在实现时固定。

### P0：冻结试点输入与报告规格

**负责人：Agent；用户参与：评价样例是否符合预期。前置：产品目标已确认。**

- [ ] P0.1 从现有 11 篇中提出 3—5 篇与职业、专业化或边界议题有关的样本；根据内容与可读性选择，记录选取理由和文档 ID。
- [ ] P0.2 建立样本清单，记录文件哈希、语言、解析状态和质量疑点；保留原 11 篇基线及当前候选结果。
- [ ] P0.3 设计一份报告样例：输入概况、议题、关联、共识、差异、互补/不确定、问题线索、证据索引。人工撰写的示意必须标为示意。
- [ ] P0.4 明确关系枚举和比较维度：一致、结论分歧、机制差异、定义差异、方法差异、情境差异、互补、暂不可比较；允许同一对论点有多个维度。
- [ ] P0.5 约定首轮按“自动生成后抽查”评价；用户无需先提出研究问题或给所有片段打标签。

**交付：**试点清单、报告规格、关系说明。开发规格存 `docs/`；包含论文全文或片段的清单/样例存本地 `outputs/`。

**验收：**输入集合能复现，报告各栏有明确含义，每项结论都有安排好的证据位置。样本范围或报告格式需要用户研究判断时，Agent 提供具体方案；独立的解析和接口准备继续进行。

### P1：生成可用于论点提取的证据单元

**负责人：Agent；用户参与：抽查疑难原文。前置：P0 样本与现有解析档案。**

- [ ] P1.1 复用现有 `document.json`、`model.txt` 与来源映射，列出试点涉及的已知问题页；不覆盖旧基线。
- [ ] P1.2 用已核查的 King 表格、郦菁脚注和 Abbott 缺字作为回归案例；阻止表格与正文拼接，给缺字内容添加质量标记。
- [ ] P1.3 表格单独保留类型和来源；无法可靠恢复结构时明确标记，不把行列内容当作连续论证。避免无差别删除有研究价值的表格证据。
- [ ] P1.4 调整仅凭“发现/认为”等提示词筛选的规则，检查它是否漏掉概念定义、条件和研究方法；为论点保留相邻上下文。
- [ ] P1.5 为片段建立稳定 ID，记录文档 ID、语言、类型、来源范围、质量状态；切分版本改变时保留旧新结果对应关系。
- [ ] P1.6 设计纯文本输入的来源格式，使用段落 ID 和字符范围；首个 PDF 原型可先运行，统一入口阶段补齐适配。
- [ ] P1.7 检查超长片段的分块和重叠策略，并在后续模型选择后确认输入长度与截断行为。

**交付：**版本化片段集、问题页处理记录、必要的回归测试；拟在独立运行目录保存 `passages.json`。

**验收：**所有片段都能定位至原文；已确认的污染案例不再无标记地进入连续论证；缺字、排除和无法解析的范围有记录。清理不能静默改变原文主张。

### P2：打通 LLM 服务并提取带证据的论点

**负责人：Agent；用户参与：提供可用服务配置和调用预算，抽查提取。前置：P1 可用证据；实际调用另需网络、凭据与额度。**

- [ ] P2.1 定义并版本化论点结构：ID、命题、原文语言、核心概念及定义、对象/地区/时期、方法、条件/限定、论点类型、证据来源、质量状态。
- [ ] P2.2 区分自身实证发现、理论论证、文献转述与无法判定；识别到引用时保存来源，没有识别到时保留未知状态。
- [ ] P2.3 保留 Schema v0.1 文献背景字段，将 `findings` 等摘要与具体论点建立映射；作者陈述的不足和系统提出的问题线索使用不同字段。
- [ ] P2.4 核查选定提供方的官方接口与模型标识，实现适配层；若使用 DeepSeek，单独验证请求、输出解析、用量、超时与限流处理。
- [ ] P2.5 先做单篇有限调用，记录模型、提示词版本、输入哈希、响应状态和实际用量；成功后扩展到试点集合。
- [ ] P2.6 为长文设计分段提取与同文献论点合并，合并时保留所有来源及适用条件；记录哪些部分实际被分析。
- [ ] P2.7 自动校验输出结构、文档归属、页码/行 ID 和引文是否来自所声明的输入；对存在但不支持命题的引用另做语义检查。
- [ ] P2.8 将空结果、证据不足、解析质量低和调用失败分开记录；只重试可恢复失败，缓存有效结果，保留失败与用量记录。

**交付：**可运行的提供方适配、带证据的论点集及调用日志；拟输出 `claims.json` 与 `run.json`。凭据留在本地环境配置中。

**验收：**真实试点调用成功，论点具有可解析的证据引用；抽查未把转述内容误作本论文独立发现，未丢失关键条件。存在问题的论点标记待查，不进入确定性综合。服务暂不可用时继续结构、适配和离线测试，并明确真实调用尚未验证。

### P3：建立多语言关联检索

**负责人：Agent；用户参与：评价抽样关联是否有价值。前置：P1 片段；论点候选生成需 P2。**

- [ ] P3.1 按中英支持、运行资源、输入长度、许可证和下载可用性核查现成模型，固定模型标识与版本；首次实验不训练模型。
- [ ] P3.2 在同一批材料上保留 TF-IDF 结果，增加语义向量检索；记录文本预处理、模型输入、分块、归一化和检索参数。
- [ ] P3.3 保留原文、统一展示语言的概括及概念对应；不能仅依赖翻译后的词汇相同就认定原概念等同。
- [ ] P3.4 从跨文献候选中关联具体论点，保留双方语境；不让同一篇文章内大量相似段落占满跨论文结果。
- [ ] P3.5 将“检索候选数量”和“报告展示数量”分开；保留各议题和各文献的覆盖情况，避免全局最高相似度垄断报告。
- [ ] P3.6 对未命中、低相似度及不同方法独有的候选抽样检查；主题接近而论点无关的情况也记录为错误。
- [ ] P3.7 分别安排中—中、英—英、中—英样本；如果首批样本缺少某组合，报告明确缺口并在 P6 扩充，不能用人工构造示例替代跨语言效果证据。

**交付：**可复现的检索配置、候选与来源、缓存和覆盖记录；拟输出 `candidates.json`。

**验收：**可在固定输入上重建候选；分别报告语言组合与方法结果。相似度仅用于排序，尚不作为一致/冲突标签。尚未建立完整相关集合时不声称测得总体召回率。

### P4：判断具体关系与可比性

**负责人：Agent；用户参与：复核典型判断与疑难项。前置：P2 论点、P3 候选及原文。**

- [ ] P4.1 给分析模型提供双方论点、研究背景、证据及必要相邻段落；不只提供相似度或关键词。
- [ ] P4.2 先检查概念指代、研究对象、时间、方法和条件是否可比较，再给出关系类型与比较维度。
- [ ] P4.3 对一致、结论分歧、机制差异、定义差异、情境差异、方法差异及互补分别给出说明；允许不相关或暂不可比较。
- [ ] P4.4 区分“作者自己提出的主张”“引述他人的观点”“描述受访者的看法”，避免把不同立场主体拼成冲突。
- [ ] P4.5 为每项关系绑定双方证据；记录关系解释中的限定条件和不确定原因。模型自报分数若被保存，只作为未校准信号。
- [ ] P4.6 对预期常见错误增加回归案例：同词不同义、同义不同词、否定、条件不同、方法词重叠、共同转述同一来源。

**交付：**`relations.json` 及可阅读的核查样例，保留候选到最终关系的处理记录。

**验收：**每项确定关系都有双方可追溯证据，解释明确指出比较维度；证据不足允许返回未知。用户抽查中发现的概念或立场混淆进入错误清单。

### P5：生成跨多篇论文的综合报告

**负责人：Agent；用户参与：评价报告的学术准确性与启发性。前置：P4 关系记录和 P2/P1 原文依据。**

- [ ] P5.1 围绕议题和可比较命题组织论点，保留多重归属及孤立项；无需固定把任意输入分成三组。
- [ ] P5.2 逐个议题建立证据表：哪些论文支持、限制、反对或补充该命题，哪些论文没有讨论。未讨论不计作反对或默认同意。
- [ ] P5.3 对每项共同认识列出实际支持论文和限定条件；有反向证据时同时展示，避免只依据论文数量做多数表决。
- [ ] P5.4 标记重复文献、共同引用来源和可能共享的数据；独立性无法判断时保留未知，不能直接重复累计为独立证据。
- [ ] P5.5 分别总结结论、机制、概念、方法与情境差异，检查组内论点是否真能共同支持归纳。
- [ ] P5.6 根据差异或适用条件生成待探索问题，逐条记录触发它的关系与证据、推测性质、后续检索或数据需求。
- [ ] P5.7 生成 JSON 与 Markdown 两份结果：后者便于阅读，前者保留论点—关系—综合—原文的连接；证据引用可直接定位。
- [ ] P5.8 输出覆盖与运行说明：输入数、完成分析数、失败/排除项、质量限制、实际使用的方法与版本。无跨文献关系时如实报告。

**交付：**第一份真实输入的自动综合报告，拟输出 `synthesis.json`、`synthesis.md` 与证据索引；人工修订和原始自动结果分别保留。

**验收：**报告包含议题、共识/差异/互补或明确的证据不足说明、来源和问题线索；每条实质判断可追溯到支持它的论点及原文。三篇以上综合不由两两相似度的传递关系直接生成。研究问题线索不被表述为已证实的领域空白。

**负责人：Agent 组织评测，User 进行研究判断。前置：P0 起草规则；关系与综合评价需 P4/P5 实际输出。**

- [ ] P6.1 保留已有 XLSX，不覆盖用户已填写内容；新增版本记录关系类型、可比性、双方证据支持、归纳忠实度、问题线索价值及理由。
- [ ] P6.2 明确人工标注和 Agent 初评字段，记录标注者、时间与规则版本；“暂缓/无法判断”与“错误”区分。
- [ ] P6.3 混合不同检索方法候选和抽样对照，隐藏检索方法与分数；按语言组合、质量问题及关系类型检查覆盖。
- [ ] P6.4 先用小批样例校准规则。可请第二位研究者复核难例；只有一位标注者时说明评价来源，不虚报标注一致性。
- [ ] P6.5 分层统计：原文定位有效率、论点证据支持情况、检索 Top-k 有用候选比例、关系判断错误、综合遗漏/错误及问题线索价值。
- [ ] P6.6 对每项统计附样本数和抽样方式；很少样本时先报告逐例结果，不把 12 对展示候选的比例推广为总体准确率。
- [ ] P6.7 将错误归因到解析、片段切分、论点提取、检索、关系判断和综合；优先修复影响最终报告的具体错误，并在固定案例上复查。
- [ ] P6.8 冻结后续评价集与规则；调参用开发集。若进入微调，按文献及重复/共享来源关系分组划分数据，减少泄漏。

**交付：**带版本的评价表、逐例误差记录、各层指标和下一轮改进决定。当前 13 条示例用于启动流程，不作为充分的模型效果证明。

**验收：**能够回答“哪些关联有价值、哪些共识或差异不准确、问题线索是否有帮助”；自动检查与人工研究判断分开记录。首轮质量阈值根据试标形成并在下一轮评价前固定，不在看到结果后调整标准。

### P7：形成统一使用入口

**负责人：Agent；用户参与：试用与反馈。前置：P5 报告可运行，P6 首轮评价完成。**

- [ ] P7.2 补齐 PDF 和纯文本适配，使两者都具有来源定位；支持单篇输入时的内容概括，并明确跨论文比较需要多篇材料。
- [ ] P7.3 用输入哈希、模型/提示词/处理版本组织缓存；修改分析条件时使相关缓存失效，避免误用旧结果。
- [ ] P7.4 支持中断恢复、分阶段重跑、部分失败报告和可见进度；避免单篇失败使已完成结果丢失。
- [ ] P7.5 将运行参数留在配置层，日常入口以文献和可选兴趣为主；失败时给出可操作说明。
- [ ] P7.6 保存每次自动结果、用户修订和运行清单；确认反馈如何作用于重跑，避免未告知地将用户反馈当作训练数据。
- [ ] P7.7 验证新目录输入、重复运行、无可比较关系、混合语言、部分损坏文件及文本输入等实际使用情形。

**交付：**统一入口、使用说明、运行示例和端到端验证记录。

**验收：**用户输入文献后，无需手动串联模块或先做标注即可得到报告；可看到失败与覆盖情况，重复运行能复用有效结果。

### 4.2 近期执行顺序与双方投入

| 优先级 | Agent 下一项工作 | 用户参与 | 等待用户反馈期间可继续的工作 |
| --- | --- | --- | --- |
| 首先 | P0 样本建议、报告规格、关系分类草案 | 评价期望输出，可指出更关心的议题 | P1 已确认污染案例的整理、P2 数据结构设计 |
| 随后 | P1 片段修复；P2 服务适配与单篇提取；P3 模型准备 | 在实际调用前配置服务和预算，抽查少量论点 | 未配置 API 时继续离线结构测试和检索准备 |
| 接着 | P3 候选、P4 关系判断、P5 第一份报告 | 查看完整结果、指出错误与有价值内容 | 自动引用检查、覆盖记录与可复现配置 |
| 再后 | P6 扩展评价、按错误修复、P7 串联入口 | 参与开发评测和试用 | 缓存、恢复、文本适配及使用说明 |

不要求用户先完成大批标注来启动实现；Agent 应先提供可检查的实际结果。服务权限、预算或必要研究判断缺失时只阻塞相应依赖，不阻止独立工作。

### 4.3 后续阶段的启动条件

- **微调**：现成模型经过评价；错误可以通过学习改善；标签量、质量与独立评价集满足实验要求。先明确要训练检索、关系分类还是生成模块，避免以“中英文训练”笼统替代任务定义。
- **扩大语料**：小规模报告可追溯，已明确运行成本与失败处理；逐步增加主题、语言和文献数量，并观察覆盖下降或误配。
- **矩阵与关系图**：关系分类和证据结构稳定，用户确实需要跨议题浏览；图中的边具有解释与来源。
- **领域新颖性判断**：在输入文献以外扩展检索范围并记录检索依据；单靠上传集合不能完成该判断。
